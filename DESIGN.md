# Chroma Flow Visualizer - Implementation Design

**Status:** Implemented as three static files, revised for unobstructed viewing, unmirrored FFT, display styles, microphone gain, BPM-based flow control with an inert settings panel, and an always-visible beat tuning section.

## Product and structure

Chroma Flow is a single-screen, full-window color visualizer. Ambient mode starts immediately and selects vivid colors on a timer. Reactive mode is opt-in and uses the microphone to drive colors, effects, beats, and an optional frequency display. All four motion effects begin off. Settings are not persisted.

The deployable app is three static files: `index.html` (semantic markup only), `style.css` (a plain linked stylesheet), and `main.js` (an ES module, so it needs to be served over HTTP rather than opened from `file://`). There is no build step, no CSS framework, and no runtime dependency: the stylesheet carries its own reset (`box-sizing`, zeroed body margins, inherited control fonts, explicit focus outlines), so nothing is pulled from a CDN except the Inter webfont, which degrades to the system sans-serif if blocked. `AudioEngine` is defined inside `main.js` and owns audio capture and analysis; the rest of the script owns UI and rendering. Every asset path is relative, so the project works unchanged from a subpath, a custom domain, or any static host. Audio is never connected to the speakers. Serve over HTTP(S); the microphone needs HTTPS or localhost.

## Scene and menu

Paint order is background color and diagonal gradient, ambient glows, enabled effects, beat ripples, radial flash, bottom canvas, center branding and click prompt, glass settings panel, and persistent MENU tab. **There is no dimming layer**: an earlier revision tinted a full-screen overlay to signal pause, and it was removed because pause should not change the brightness of the image. The layer stack and the effects are hidden from assistive technology, but the center `h1` stays exposed so the page still has a heading; only the marketing overline and the pointer-only CLICK TO SHIFT prompt are hidden.

The settings panel is open on startup, and the MENU tab ships with `aria-expanded="true"` so its state matches what is on screen before any script runs. **Closing the menu hides the entire central CHROMA FLOW composition, including its overline and CLICK TO SHIFT prompt**, leaving the color and effects unobstructed. Only the small MENU tab remains. Reopening the menu restores the central composition. This behavior is the same in ambient/reactive, paused/playing, desktop/mobile, and fullscreen states. The document title and the brand in the settings panel remain available independently of the central composition.

On wide screens the panel is left-aligned; below 600 px it is a scrollable bottom sheet. The close and MENU buttons transfer keyboard focus to one another. A background click changes the color (or reactive hue bias), but the settings panel itself is inert: a delegated guard excludes the whole `.hud` subtree plus `button`, `input`, `summary`, and links. Clicking anywhere inside the menu — panel background, labels, readout text, scrollbar drag — therefore never re-keys the color, so the hex and RGB values stay still and selectable long enough to be copied. Space pauses only when focus is outside interactive or editable elements. Fullscreen button state follows `fullscreenchange`.

## Color and playback

Ambient hue is random from 0-359 degrees, saturation from 62-91%, and lightness from 42-61%. Values are converted to RGB and uppercase hex and displayed in the HUD. Flow speed is **an absolute beats-per-minute slider from 60 to 240, defaulting to 120 BPM**, and is labelled in BPM rather than in abstract steps because BPM is a unit the user can reason about. One color is selected per beat, so the ambient timer period is `round(60000 / bpm)` ms: 1000 ms at 60 BPM, 500 ms at the 120 BPM default, and 250 ms at 240 BPM. Flow is deliberately **not** a tiered step scale: 120 BPM is the midpoint of the range, and a 20-step tier control cannot express that, since step 15 of 20 already sits about 94% of the way up its own range. Background transitions take 120 ms in standard motion.

With microphone capture active there is no ambient interval. Hue follows `(centroid * 460 + hueBias + bass * 24) mod 360` by the shortest route around the color wheel with exponential easing at `0.6 + (flowBpm - 60) / 180 * 3.45` — 0.6/s at 60 BPM, about 4.05/s at 240 BPM, and 1.75/s at the 120 BPM default. Saturation is `clamp(58 + level * 34, 40, 96)` and lightness is `clamp(38 + level * 26 + bass * 6, 20, 68)`. The complementary hue supplies accents. Background clicks re-roll `hueBias` without restarting capture.

**Pause freezes the automatic progression, not the image.** No overlay is dimmed and no brightness changes: the only pause affordances are that effect animations and ripples hold still, the live dot turns amber and stops pulsing, the HUD reads PAUSED SESSION, and the button offers RESUME. Pause stops the ambient timer, the frame counter, effect motion, ripples, flash, and canvas drawing; the microphone keeps analysing audio and the level/BPM/beat HUD may still update. Beats during pause do not queue visual events. The microphone button explicitly ends capture. On resume rendering continues from the frozen visual state.

**A background click still re-keys the color while paused**, because a click is an explicit user action rather than part of the automatic cycle. The pause guard therefore lives on the timer tick (`selectAmbientColor`), not on the color picker (`applyRandomColor`), so a click reaches the picker in either state. In ambient mode it applies a fresh random color immediately. In reactive mode it re-rolls `hueBias`; since the render loop does not paint while paused, the new bias is resolved straight away from the latest audio snapshot so the click is never a no-op, falling back to a random ambient color before any audio has been analysed. Each click increments the frame counter, because a real color change was applied.

## Effects

Orbiting objects include three glow orbs, a square, and a triangle; shape paths change when enabled and on audible beats. Color waves are three staggered rings, liquid flow is three soft-light blobs, and prism shift is two screen-blended bands. **All four start off and are toggled one at a time from their own buttons; there is no bulk MIX ALL control.** Enabling orbit re-rolls its shape paths.

Motion speed is independent of flow speed, is **a 20-step tier slider defaulting to step 15**, and uses the same logarithmic interpolation. The anchors are orbit 30/20/13/7/3.2 s, waves 14/9/6/3.6/1.7 s, liquid 28/19/12/7/3.6 s, and prism 22/15/10/5.5/2.8 s; at the default the rendered orbit loop is 7.23 s and the wave loop 3.70 s, matching the feel of the old step 4.

## Settings

The HUD contains brand/live state and close, color readout/frame, pause/fullscreen, flow speed, motion speed, effects, and audio settings. Audio settings contain microphone toggle and status, level meter, BPM and beat count, FFT spectrum toggle, **BARS/WAVE display style buttons**, **microphone gain slider**, and a BEAT FINE-TUNING disclosure for sensitivity. **The disclosure is open by default**, so the sensitivity slider is visible on first paint instead of hiding one interaction behind a summary. Both speed sliders and the sensitivity slider publish an `aria-valuetext` in plain language (for example `120 beats per minute, one color every 500 milliseconds` on flow, and `FAST, one orbit every 7 seconds` on motion) so the real rate is announced rather than a bare number, and each label is written from state on startup rather than trusted from the markup.

Display style defaults to **BARS**, and spectrum visibility defaults on unless reduced motion is active at startup. Choosing WAVE draws a connected, filled **FFT frequency-response envelope** rather than a time-domain oscilloscope trace. It uses the same frequencies and input data as BARS, so both modes represent the entire available frequency range from left (low) to right (high). Style and visibility can be changed while listening; a hidden or paused canvas is not animated.

Gain defaults to **1.0x**, with a native range slider from 1.0x to 8.0x in 0.5x increments. Gain can be adjusted before or during capture. The chosen value stays in memory across microphone restarts but resets on page reload. The level meter and all audio analysis use the boosted input. Large gain values can clip; the user can lower the slider to restore headroom.

Sensitivity remains a five-step slider inside BEAT FINE-TUNING, default 3, with multipliers 1.85/1.58/1.36/1.18/1.05. Controls use native buttons, sliders, and disclosure with visible labels, state attributes, and keyboard focus indication.

## Capture and analysis

The audio graph is `MediaStreamAudioSourceNode -> GainNode -> AnalyserNode`, with no connection to `AudioContext.destination`. Microphone constraints disable echo cancellation, noise suppression, and automatic gain control. The analyser FFT size is 2048 and smoothing is 0.72. Gain changes are applied smoothly to the GainNode. Insecure contexts fail before requesting permission.

One requestAnimationFrame loop while listening reads frequency and time-domain buffers. It calculates smoothed RMS level, noise-floor-lifted bass (20-180 Hz), mid (180 Hz-2.2 kHz), treble (2.2-14 kHz), normalized centroid, beat, beat envelope, and onset strength. Each band has a 48-frame running average. Onsets must exceed the band's average times its sensitivity multiplier and a 0.035 minimum, be rising, follow a 16-frame warm-up, and be at least 0.16 s apart. The detector is three-band, not bass-only. BPM uses up to ten intervals of 0.28-1.30 s, requires three qualifying intervals, and shows only 55-200 BPM; a gap longer than 1.30 s clears it.

During a pending permission request, a second activation cancels the pending start. A late grant stops its tracks rather than activating capture. Track-ended and pagehide also tear down the graph. Teardown stops tracks, disconnects nodes, closes the context, resets analysis, resumes ambient scheduling, and repaints when unpaused. Inline status messages cover insecure pages, denied permission, missing/busy microphones, unsupported capture, overconstrained input, and unknown errors.

## Reactive visuals and FFT

The renderer publishes `--level`, `--bass`, `--mid`, `--treble`, `--beat`, and `--accent`. A beat creates an accent ripple (at most nine live), moves orbit shapes when enabled, and drives the radial flash. HUD readouts update at approximately 10 Hz. Frame deltas are clamped after background-tab gaps. The canvas backing store uses ResizeObserver and caps device-pixel ratio at 2.

The bottom FFT strip draws **72 logarithmically spaced frequency samples, left-to-right without mirroring**, beginning at about 30 Hz and ending at **16 kHz when the input sample rate supports it**. The actual upper bound is `min(16000, (frequencyBinCount - 1) * sampleRate / fftSize)`, because bins above Nyquist do not exist. The displayed rightmost label is 16 KHZ when available; otherwise it reports the reachable maximum instead of implying nonexistent frequency data. BARS uses glowing colored bars, white caps, and decaying peak markers. WAVE draws a glowing continuous frequency envelope with a translucent fill. Both show a baseline and 60 Hz / 1 kHz frequency markers, and both use the same left-to-right logarithmic scale. The strip shortens on phone-sized screens.

## Reduced motion, defaults, and verification

Reduced motion stops effect keyframes and pulsing indicators and suppresses ripples and flash. Ambient timing never goes below 1100 ms and has a longer transition. Reactive color application is limited to twice per second with a gentler transition. Spectrum starts hidden under reduced motion but remains manually available. Changes to the motion preference during the session update behavior without changing sliders.

Defaults: playing, ambient, menu open with center title visible, **flow 120 BPM, motion step 15**, sensitivity 3, gain 1.0x, effects off, beat fine-tuning open, spectrum on except under reduced motion, and FFT style BARS. Reloading restores these defaults.

Manual verification should cover ambient speeds and click-to-shift; **clicking the background while paused in both ambient and reactive mode, confirming the color changes each time and that the image is not dimmed**; each effect individually and all four stacked; a full sweep of the flow slider across 60-240 BPM and of the motion slider across steps 1-20, checking that the flow label and `aria-valuetext` track the BPM reading and that the ambient period matches `60000 / bpm` (1000 ms at 60, 500 ms at the 120 default, 250 ms at 240), while every motion step yields a distinct rate, its tier label tracks the step, and the `--fill` track and the CSS duration variables update; **clicking everywhere inside the settings panel — background, section labels, hex and RGB readout, frame readout, scrollbar drag — confirming the color does not change and the hex and RGB text can be selected and copied;** pause/resume and microphone capture while paused; close/reopen on desktop and mobile (especially center-title visibility) plus the MENU tab's `aria-expanded`; keyboard/focus/fullscreen; gain adjustments before and during capture and clipping at high settings; BARS and WAVE frequency progression without mirroring and 16 kHz label on supported sample rates; low-sample-rate fallback; spectrum resize; permission rejection/cancellation/late grant/disconnection; beat and BPM clearing; and reduced-motion changes during a session. There is no automated test suite or build output.
